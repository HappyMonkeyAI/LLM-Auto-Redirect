# CONTEXT — LLM Auto Redirect

## Stack and runtime assumptions

- **Runtime Environment**: WordPress 5.0+ / PHP 7.4+
- **Integrations**: Relies on the "Redirection" WordPress plugin by John Godley (checks for table prefix `redirection_404` and class `Red_Item`).
- **LLM Providers Supported**:
  - **Ollama**: Local instance support using the `/api/generate` endpoint.
  - **OpenAI / LM Studio**: OpenAI-compatible endpoint supporting optional API key authentication and custom base URLs.
  - **OpenRouter**: Cloud-based model provider utilizing the standard completions endpoint.
  - **Google Gemini**: Gemini API (e.g. `gemini-1.5-flash`, `gemini-pro`).

## Non-negotiable rules

- **Credential Handling**: Provider API keys must never be rendered back into HTML or logs. Blank key submissions preserve saved values; explicit clear controls remove them.
- **URL Validation**: All suggestions generated by the LLMs must be absolute, valid URLs matching `FILTER_VALIDATE_URL` and exactly match one of the approved page targets supplied in the prompt. The manual admin target field remains available for deliberate overrides.
- **Admin Control**: The plugin only suggests redirects in the admin panel; it must NOT create redirects automatically on front-end hits unless explicitly commanded.
- **Safety Fallback**: Always implement regex-based filtering to strip thinking blocks, markdown formatting, and preamble text to handle unpredictable LLM outputs.
- **Keep Documentation Integrated**: Code comments, docstrings, and help texts must be kept intact unless explicitly requested to be changed.

## Workflow protocols

- **Multi-Agent Coordination**: Claim tasks and lock files using the scripts in `scripts/` before beginning implementation slices.
- **Verification Gating**: Run `python3 scripts/bootstrap-validate.py` or verification tests before committing changes.

## Resolved architecture decisions

- **ADR-001**: Structured Outputs (JSON Schema) for OpenAI-compatible providers to enforce format constraints.
- **ADR-002**: Multi-layered response cleaning (thought removal, regex URL search, JSON extraction) to handle reasoning models like DeepSeek-R1.

## What not to do

- **No Hardcoded Keys/URLs**: Do not store API credentials, custom URLs, or tokens in the code.
- **No Direct Creation in AJAX Suggest**: Suggest AJAX handler only returns suggestions. Do not call `Red_Item::create` inside `handle_llm_suggestion_ajax()`.

## Project-specific guidance

- Use the settings page fields to configure custom local models (like `qwen` or `deepseek` in LM Studio).
- Ensure `max_tokens` is large enough (default 2048) for reasoning models to prevent premature cutoff.
